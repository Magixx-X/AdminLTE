# 上级医师查房记录规范率模板

模板 SQL 使用同目录 rounds_record.sql，字段配置参照 rounds_record.json；这些文件是待院方验证的模板，不会自动写入运行数据库。名称可用“上级医师查房记录规范率（全院）”，但实际规则目前只判断入院48小时内是否存在标题含“查房”的记录，并未核验医师级别、签名、正文完整性或记录作废状态。

参数 schema 填写 JSON 数组，仅定义 start_date / end_date，类型 date，均必填。结束日期使用 end_after=start_date，表示严格晚于开始日期；开始包含、结束不含。例如查2026年10月，start_date=2026-10-01、end_date=2026-11-01。查某一天时结束填写次日。日期参数按日期对象绑定，SQL 不再 TO_DATE。

查询页的开始月份/结束月份仍需填写，代表任务自然月；与自定义日期取交集。查10月选2026-10至2026-10；跨月选择覆盖日期区间的所有月份。多月会分别返回各月汇总，不会自动生成全期间去重总率；每月分子分母不能直接相加求全期间患者去重率。

排序字段白名单推荐 []，保留 SQL 的 sort_flag 顺序，使汇总在前。若填 ["sort_flag"] 则允许预览按该字段排序，但降序会将汇总移到最后。当前白名单仅接受英文字段名，不能填写“患者姓名”等中文别名，也不能写 ASC/DESC、表名或 SQL 表达式；它只控制有界预览排序，不改变导出 SQL 顺序。

数据范围策略填写 {"kind":"all","query_timeout":60}。全院策略每月只执行一次，不需要 :scope_department，也不要求用户配置科室范围，但仍要求查询菜单权限和该模板的执行/查看/导出授权。发布时必须勾选范围审核、全院范围与接收者授权确认；Oracle 另需真实医院SQL验证及证据。原 department_bind 策略保持原规则，不能简单删除其科室条件。

版本摘要使用 rounds_record.json 中的 summary，明确筛选口径、去重单位、全院范围、时间边界、48小时判断及跨月限制。当前保留原 SQL 的 COUNT(DISTINCT patient_id) 分子/分母口径，明细按住院记录展示：同一患者多次住院仍可能计为一个患者。若应按住院人次统计，需要另行明确 patient_id+visit_id 的唯一性，并修改分子分母，不能仅改摘要。无出院患者时显示“无样本”。

发布前核对真实数据库表/字段、记录有效状态、姓名与住院号访问权限、执行计划与合理超时，并以真实结果验证；平台参数契约检查不等同 Oracle SQL 实测通过。不要在平台 SQL 中加入 CREATE VIEW、分号或 SQL*Plus 的 / 结束符。
